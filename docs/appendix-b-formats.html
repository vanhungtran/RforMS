MS File Format Reference

A mass spectrometer is a digital sensor that outputs raw binary streams. Open scientific progress requires standardized, vendor-neutral file formats that decouple data acquisition from data analysis.

Mass spectrometry experiments pass through multiple data representations between physical ion detection and final statistical modeling: 1. Closed vendor formats generated in real time by instrument hardware controllers. 2. Standardized open XML and binary containers for raw spectra and chromatograms. 3. Structured tabular and relational formats for peptide identifications, protein inferences, and quantified metabolite feature tables.

This appendix provides a comprehensive technical reference for the mass spectrometry file formats supported across the Bioconductor and CRAN ecosystems, detailing their underlying schemas, binary compression algorithms, controlled vocabularies, and conversion protocols.

1. Proprietary Vendor Formats

Mass spectrometer manufacturers record data in proprietary, closed-source formats optimized for proprietary acquisition software and fast disk writes.

WarningVendor File Preservation Policy

Proprietary vendor files should be treated as read-only primary evidence. Never modify, overwrite, or re-save raw vendor files in place. Furthermore, multi-component formats (such as Agilent .d, Bruker .d, and SCIEX .wiff/.wiff.scan) represent unified file systems: moving, renaming, or deleting sub-files corrupts the internal pointers, rendering the entire dataset unreadable.

Vendor Native Format / Extension Internal Structure Native Reading Mechanism
Thermo Fisher Scientific .raw Single compound OLE/COM binary container Vendor Foundation DLLs (Windows) or ThermoRawFileParser (cross-platform .NET)
SCIEX .wiff + .wiff.scan (and .wiff2) Dual-file pair: .wiff stores experiment metadata and method trees; .wiff.scan stores raw binary spectral streams WiffReader DLLs or ProteoWizard
Agilent Technologies .d Hierarchical directory containing MSScan.bin, MSPeak.bin, and XML schema files MassHunter MIDAC / ProteoWizard
Bruker Daltonics .d (directory) Directory containing SQLite databases (analysis.tdf / analysis.tsf for timsTOF; analysis.baf for Q-TOF) Bruker Compass SDK / timsR / opentims

Shimadzu .lcd Proprietary LCMSsolution database format LabSolutions / ProteoWizard

2. Open Standards for Raw Spectra and Chromatograms

To ensure long-term reproducibility and vendor neutrality, the Human Proteome Organization Proteomics Standards Initiative (HUPO-PSI) developed open, community-governed data standards based on Extensible Markup Language (XML) and hierarchical data containers.

mzML (HUPO-PSI Standard)

mzML is the universal community standard for representing raw mass spectrometry data (Martens et al. 2011). It merges the best features of earlier formats (ISB mzXML and Waters mzData).

An mzML document is divided into four major structural blocks:

+-------------------------------------------------------------------------------+
|                             mzML XML Architecture                             |
+-------------------------------------------------------------------------------+
| <cvList>                     Controlled vocabularies (PSI-MS CV terms)        |
| <fileDescription>            File provenance, source vendor files, contacts   |
| <referenceableParamGroupList> Reusable metadata templates                     |
| <sampleList>                 Biological sample definitions                    |
| <instrumentConfigurationList> Physical components (source, analyzer, detector)|
| <dataProcessingList>         Centroiding, smoothing, thresholding algorithms  |
| <run>                                                                         |
|   ├── <spectrumList>         Array of MS1, MS2, MS3 spectra                   |
|   └── <chromatogramList>     TIC, BPC, and SRM transition traces              |
| <indexList> (in indexedmzML) Fast byte-offset seek table for O(1) random access|
+-------------------------------------------------------------------------------+

The PSI-MS Controlled Vocabulary (CV)

mzML achieves strict semantic interoperability through the PSI-MS Controlled Vocabulary. Every instrument parameter, scan filter, and processing algorithm is encoded as a standardized CV term with a unique accession:

<cvParam cvRef="MS" accession="MS:1000511" name="ms level" value="1"/>
<cvParam cvRef="MS" accession="MS:1000127" name="centroid spectrum" value=""/>
<cvParam cvRef="MS" accession="MS:1000016" name="scan start time" value="124.5" unitCvRef="UO" unitAccession="UO:0000010" unitName="second"/>

Because software parses unambiguous accession keys (MS:1000511) rather than English text strings, mzML files are completely immune to vendor spelling differences.

Binary Data Encoding and Numpress Compression

Spectra store thousands of (m/z, \text{intensity}) coordinate pairs per scan. Storing these numbers as plain text ASCII inside XML would result in massive, unmanageable files.

mzML solves this by encoding numerical arrays as Base64 binary streams: - m/z Arrays: Stored as 64-bit IEEE 754 floating-point numbers to maintain sub-ppm mass accuracy. - Intensity Arrays: Stored as 32-bit or 64-bit floating-point numbers. - zlib Compression: Binary arrays are compressed using DEFLATE/zlib, reducing file size by 50%–70%. - MS-Numpress: Advanced lossy compression algorithms designed specifically for mass spectrometry: - NumpressLin: Fixed-point linear predictive compression for monotonically increasing m/z arrays. - NumpressPic: Truncation-based compression for positive integer ion count intensities. - NumpressSlo: Short-logged float compression for high dynamic range intensities.

indexedmzML: O(1) Random Access

Standard XML files require parsers to read sequentially from line 1 to find a spectrum located at the end of the file. For a 10 GB LC-MS run containing 80,000 scans, this would make random access prohibitively slow.

The indexedmzML standard wraps the mzML document with an <indexList> at the very end of the file. The index maps every spectrumID directly to its physical byte offset:

<index name="spectrum">
  <offset idRef="scan=1">24810</offset>
  <offset idRef="scan=2">58920</offset>
  <offset idRef="scan=3">93410</offset>
</index>
<indexListOffset>104857600</indexListOffset>

When an R package such as Spectra (using MsBackendMzR) opens an indexedmzML file, it immediately seeks to the final bytes of the file, loads the byte-offset index into memory, and can then extract any individual spectrum in sub-millisecond time without parsing the rest of the file.

imzML (Imaging Mass Spectrometry)

The imzML format extends mzML to spatial mass spectrometry imaging (MSI; Chapter 27) (Schramm et al. 2012).

Because an imaging dataset contains hundreds of thousands of spatial pixels, storing XML tags for every pixel creates unacceptable file bloat. imzML solves this by separating metadata from binary data into an inseparable file pair:

  1. sample.imzML (XML Metadata): Standard mzML XML containing instrument configuration, run parameters, and spatial coordinate tags (MS:1001983 for x position, MS:1001984 for y position). However, the <binaryDataArray> elements contain no numbers—only byte offsets and lengths pointing into the binary file.
  2. sample.ibd (Imaging Binary Data): A pure, contiguous binary data blob containing raw floating-point m/z and intensity arrays packed sequentially pixel-by-pixel.
+--------------------------+        Byte Offset Seek        +--------------------------+
|       sample.imzML       | ---------------------------->  |        sample.ibd        |
|  (XML Index & Spatial x,y|                                |  (Raw Binary Spectral    |
|   Coordinates)           | <----------------------------  |   Arrays)                |
+--------------------------+                                +--------------------------+

3. Open Standards for Identifications and Feature Quantification

mzIdentML (.mzid)

mzIdentML is the HUPO-PSI community standard for peptide-spectrum matches (PSMs), protein inferences, and search-engine parameters (Chapter 11) (Jones et al. 2012).

It provides an audit trail capturing: - Target-decoy database searching parameters (enzyme specificity, missed cleavages, precursor mass tolerances). - Fixed and variable chemical modifications (e.g., carbamidomethylation, methionine oxidation, phosphorylation). - Candidate matches per spectrum (<SpectrumIdentificationItem>), ranked by search engine scores (Mascot ion score, MS-GF+ raw score, Comet expectation value). - Target/decoy assignments (isDecoy="false" or isDecoy="true"), false discovery rate (FDR) q-values, and posterior error probabilities (PEP). - Protein ambiguity groups (bipartite graphs mapping shared peptides to candidate proteins).

mzTab and mzTab-M

While mzML and mzIdentML are detailed XML representations, data analysts frequently require simple, tabular structures for statistical modeling.

mzTab is a tab-delimited file standard that stores both identification evidence and quantitative abundances across experimental samples in a single human-readable document (Griss et al. 2014). mzTab-M specializes this standard for metabolomics and lipidomics (Hoffmann et al. 2019).

An mzTab file is structured into distinct line-prefixed sections:

MTD  mzTab-version    1.0.0
MTD  study_variable[1]-description   Control Group (HeLa vehicle)
MTD  study_variable[2]-description   Treated Group (HeLa 10uM Bortezomib)
PRH  accession  description  taxid  species  protein_abundance_study_variable[1]  protein_abundance_study_variable[2]
PRT  P02768     Albumin      9606   Human    12845000                             11920000
PEH  sequence   accession    charge mass_to_charge  peptide_abundance_study_variable[1]
PEP  EACFAVEGPK P02768       2      555.26          845000

4. Conversion Protocols: From Vendor Data to Open Standards

To build reproducible R workflows, proprietary vendor files must be converted to indexedmzML. Two production-grade tools dominate the field:

1. ProteoWizard msconvert

msconvert is the reference converter supported by the ProteoWizard consortium. It runs natively on Windows or within Docker containers incorporating Windows emulation or vendor Linux libraries.

Optimal Conversion Recipe for Untargeted Metabolomics and Proteomics:

msconvert sample.raw \
  --mzML \
  --filter "peakPicking vendor msLevel=1-" \
  --filter "zeroSamples removeExtra" \
  --zlib \
  --outdir ./mzml_converted
  • --mzML: Specifies output format as mzML (defaults to indexedmzML).
  • --filter "peakPicking vendor msLevel=1-": Executes vendor-algorithm centroiding on all MS levels (MS1, MS2). This is critical: vendor centroiding uses instrument-specific peak shape models, yielding superior mass accuracy compared to generic mathematical centroiders.
  • --filter "zeroSamples removeExtra": Strips redundant zero-intensity baseline padding, reducing file size by 30%.
  • --zlib: Enables lossless binary compression.

2. ThermoRawFileParser

ThermoRawFileParser is an open-source, cross-platform (.NET Core) utility developed specifically to parse Thermo .raw files on Linux, macOS, and Windows without requiring commercial vendor software licenses (Hulstaert et al. 2020).

# Cross-platform command for automated Linux pipelines
ThermoRawFileParser.sh \
  -i=sample.raw \
  -o=./mzml_converted \
  -f=2 \
  -m=0
  • -f=2: Outputs standard indexedmzML.
  • -m=0: Exports metadata and spectra simultaneously.

Summary

  • Proprietary vendor formats (.raw, .wiff, .d) are closed and should be preserved as read-only primary evidence.
  • indexedmzML is the gold standard for raw spectra, providing semantic consistency via the PSI-MS controlled vocabulary, compact size via zlib/numpress compression, and O(1) random access via byte-offset tables.
  • imzML splits metadata and binary signals into an XML (.imzML) and binary (.ibd) pair to support massive spatial imaging datasets.
  • mzIdentML and mzTab provide vendor-neutral formats for search engine identifications, FDR statistics, and sample-level quantification matrices.
  • Vendor peak-picking (msconvert --filter "peakPicking vendor") should always be enabled during conversion to leverage instrument-specific centroiding algorithms.

## Summary

- Proprietary vendor formats (`.raw`, `.wiff`, `.d`) are closed and should be preserved as read-only primary evidence.
- **`indexedmzML`** is the gold standard for raw spectra, providing semantic consistency via the PSI-MS controlled vocabulary, compact size via zlib/numpress compression, and $O(1)$ random access via byte-offset tables.
- **`imzML`** splits metadata and binary signals into an XML (`.imzML`) and binary (`.ibd`) pair to support massive spatial imaging datasets.
- **`mzIdentML`** and **`mzTab`** provide vendor-neutral formats for search engine identifications, FDR statistics, and sample-level quantification matrices.
- Vendor peak-picking (`msconvert --filter "peakPicking vendor"`) should always be enabled during conversion to leverage instrument-specific centroiding algorithms.
