10  Audit Peptide-Spectrum Matches and Build an Identification Report

  • Show All Code
  • Hide All Code
  • View Source

A database search engine returns a list of peptide–spectrum matches (PSMs) — candidate assignments of MS/MS spectra to peptide sequences. Not every PSM is correct. This chapter shows you how to load a real PSM table into R, apply score-based FDR filtering with target–decoy statistics, flag common failure modes (shared peptides, missed cleavages, charge-state anomalies, contaminants), and assemble a clean identification report that can be handed to quantification workflows.

WarningThe One Mistake to Avoid

Filtering PSMs by a raw score threshold. A score cutoff gives you no control over the actual false-discovery rate. Always estimate FDR against decoy hits and filter to a target FDR instead.

10.1 Learning Objectives

By the end of this chapter you will be able to:

  • Load a search-engine PSM table into R and understand its columns
  • Apply score-based false-discovery-rate (FDR) filtering using target–decoy statistics
  • Diagnose common PSM failure modes: shared peptides, missed cleavages, charge-state anomalies, and contaminant hits
  • Assemble a clean, quantification-ready identification report

10.3 Understanding Proteomics Workflows

The typical bottom-up proteomics workflow involves:

  1. Sample preparation: Protein extraction, digestion (usually with trypsin)
  2. LC-MS/MS analysis: Liquid chromatography coupled to tandem mass spectrometry
  3. Database searching: Matching MS/MS spectra to peptide sequences
  4. Protein inference: Assembling peptides into protein identifications
  5. Quantitative analysis: Comparing protein abundances across samples

This chapter covers step 3’s output (the PSM table) and the audit that must happen before step 4. Chapter 11 picks up protein inference from the clean PSM table this chapter produces.

ImportantKey Proteomics Concepts
  • PSM (Peptide-Spectrum Match): One MS/MS spectrum matched to one peptide sequence
  • FDR (False Discovery Rate): Typically controlled at 1% using target-decoy approach
  • Protein Parsimony: Minimal set of proteins explaining observed peptides
  • Missing Values: Can occur at PSM, peptide, or protein level - handle appropriately

10.5 The Target–Decoy FDR Framework

Before writing any filter code, you must understand how the false discovery rate is actually estimated in proteomics. Database search engines do not know which PSMs are correct — they only produce scores. The target–decoy strategy solves this with a simple but powerful idea:

  1. Concatenate your real protein database with a decoy database — reversed or shuffled sequences that cannot exist in nature.
  2. Search against the combined database. Every PSM either matches a target (real) or a decoy (fake) sequence.
  3. Count decoy matches as false positives. Because decoys are biologically impossible, any PSM assigned to a decoy must be incorrect. Assuming false positives are equally likely among target and decoy matches:

\text{FDR} = \frac{\text{Number of decoy PSMs above score threshold}}{\text{Number of target PSMs above score threshold}}

This gives you the PSM-level FDR — the expected proportion of incorrect identifications among all PSMs that pass the score cutoff. The standard threshold is 1 % FDR at the PSM level.

The PSM-to-protein FDR gap. A critical and frequently overlooked point: controlling FDR at 1 % at the PSM level does not guarantee 1 % FDR at the protein level. If a false PSM maps to a protein with no other evidence, that protein becomes a false identification. Conversely, if many true PSMs map to one protein, a single false PSM among them may not change the protein call. Protein-level FDR must be estimated separately — typically by applying the same target–decoy logic at the protein-group level, or by using a picked-protein FDR strategy (Savitski et al., 2015).

In practice: - PSM-level FDR ≤ 1 % — the minimum standard for publication - Peptide-level FDR ≤ 1 % — stricter, requires at least 2 PSMs per peptide - Protein-level FDR ≤ 1 % — the gold standard; proteins with only one peptide (“one-hit wonders”) are the most vulnerable to false discovery

10.5.1 Computing FDR at a Score Threshold

This bundled file already carries decoy hits from the search (accessions prefixed XXX_), so we can compute the formula above directly instead of trusting a pre-filtered table:

Code 
table(psm$isDecoy)

FALSE  TRUE 
 2906  2896
Code 
fdr_at_threshold <- function(psm, score_col, threshold) {
  above <- psm[[score_col]] >= threshold
  n_decoy  <- sum(above & psm$isDecoy)
  n_target <- sum(above & !psm$isDecoy)
  n_decoy / n_target
}

score_grid <- seq(5, 20, by = 1)
fdr_curve <- data.frame(
  score = score_grid,
  fdr   = sapply(score_grid, fdr_at_threshold, psm = psm, score_col = "MS.GF.RawScore")
)

ggplot(fdr_curve, aes(score, fdr)) +
  geom_line(color = "steelblue", linewidth = 0.8) +
  geom_hline(yintercept = 0.01, linetype = "dashed", color = "#B2182B") +
  labs(title = "Empirical target-decoy FDR vs. score threshold",
       x = "MS-GF+ RawScore threshold", y = "FDR (decoys / targets)") +
  theme_minimal()

Raising the score threshold shrinks the decoy fraction — this is the curve every FDR filter is implicitly walking.

10.5.2 Filtering with PSMatch

PSMatch provides purpose-built filters instead of hand-rolling the threshold search. Applied one step at a time:

Code 
# Step 1: keep only the best-ranked match per spectrum
psm_rank1 <- filterPsmRank(psm)

# Step 2: remove decoy hits (do this *after* using them to pick a threshold)
psm_target <- filterPsmDecoy(psm_rank1)

nrow(psm); nrow(psm_rank1); nrow(psm_target)
[1] 5802
[1] 5487
[1] 2751

Or in one call, which applies decoy removal, rank filtering, and shared-peptide filtering together:

Code 
psm_clean <- filterPSMs(psm)
nrow(psm_clean)
[1] 2666
Tip

filterPSMs() is convenient for a quick pass, but run the steps separately (as above) the first time you touch a new search result — you want to see each removal count individually, not just the final total, so an unexpectedly large drop at one step doesn’t slide past unnoticed.

10.6 Diagnosing PSM Failure Modes

A PSM table that has passed FDR filtering can still contain systematic problems that FDR filtering does not catch. Four are worth checking on every search result.

10.6.1 Missed Cleavages

Trypsin cleaves after K or R, except when followed by P. A peptide with internal (non-terminal) K/R residues represents a site trypsin should have cut but did not — a missed cleavage.

Code 
count_missed_cleavages <- function(seq) {
  sites <- gregexpr("[KR](?!P)", seq, perl = TRUE)[[1]]
  n <- if (sites[1] == -1) 0L else length(sites)
  # the terminal residue's own K/R *is* the expected cleavage site, not missed
  if (substr(seq, nchar(seq), nchar(seq)) %in% c("K", "R")) n <- n - 1L
  max(n, 0L)
}

psm_target$missed_cleavages <- sapply(psm_target$sequence, count_missed_cleavages)

ggplot(as.data.frame(psm_target), aes(x = factor(missed_cleavages))) +
  geom_bar(fill = "steelblue") +
  labs(title = "Missed cleavages per PSM",
       x = "Missed cleavages", y = "PSM count") +
  theme_minimal()

A well-controlled tryptic digest is usually dominated by 0–1 missed cleavages. A distribution this broad is worth a second look at digestion conditions before trusting downstream quantification — the missed-cleavage rate is a real, searchable diagnostic, not just a filter setting.

10.6.2 Charge-State Anomalies

Tryptic peptides overwhelmingly carry 2+ or 3+ charge in electrospray. Rare charge states deserve scrutiny — 1+ often means a poorly fragmented or contaminant ion, and very high charge states (5+, 6+) are uncommon enough to double-check manually.

10.6.3 Contaminant Hits

Search databases are normally supplemented with a contaminant database (keratins, trypsin itself, BSA) precisely so that these common laboratory proteins get identified and can be filtered out rather than silently contaminating a real hit list. Look for them directly in the protein descriptions:

Code 
contaminant_hits <- as.data.frame(psm_target) |>
  filter(grepl("keratin|trypsin|albumin|contaminant", DatabaseDescription, ignore.case = TRUE))

unique(contaminant_hits$DatabaseDescription)
[1] "sp|P00761|TRYP_PIG Porcine Trypsin for sample preparation OS=Sus scrofa PE=1 SV=1"
[2] "sp|P02769|ALBU_BOVIN Serum albumin OS=Bos taurus GN=ALB PE=1 SV=4"

This search genuinely recovers a contaminant: porcine trypsin — the digestion enzyme itself, identified via its own autolysis products. This is the single most common contaminant in bottom-up proteomics and a useful sanity check that the search database was set up correctly.

10.6.4 Shared Peptides

Not every peptide maps to a single protein. describePeptides() and describeProteins() summarise the peptide-to-protein mapping before shared peptides are removed, so you can see the scale of the problem in your own data:

Code

Code 
describeProteins(psm_target)

Some peptides here match more than one protein accession, and some proteins are supported only by such shared peptides. makeAdjacencyMatrix() turns this into a peptide × protein matrix, and ConnectedComponents() groups the graph into clusters that must be resolved together — you cannot decide which protein a shared peptide belongs to by looking at that protein alone:

10.8 Summary

  • A PSM table is a hypothesis list, not a ground truth — every row needs auditing before it feeds quantification.
  • Target–decoy FDR, not a raw score cutoff, is the only defensible way to set a confidence threshold: FDR = decoy PSMs / target PSMs above a given score.
  • PSMatch::filterPsmRank(), filterPsmDecoy(), and filterPsmShared() implement the three filtering steps that turn a raw search result into a clean identification list; filterPSMs() runs all three at once.
  • Missed cleavages, charge-state anomalies, and contaminant hits are systematic failure modes that FDR filtering alone does not catch — check them explicitly.
  • Shared peptides — those matching more than one protein — must be resolved before protein-level claims are trustworthy. describePeptides(), describeProteins(), and makeAdjacencyMatrix()/ConnectedComponents() make the scope of the problem visible; Chapter 11 resolves it into protein groups.

10.9 Exercises

  1. FDR sensitivity. Recompute the empirical FDR curve using MS.GF.SpecEValue instead of MS.GF.RawScore (note: lower E-values are better, so the threshold direction flips). At what E-value does the empirical FDR cross 1%?
  2. Missed cleavages vs. charge state. Is the number of missed cleavages associated with precursor charge state in this dataset? Produce a boxplot of missed_cleavages grouped by chargeState and interpret it.
  3. Order of operations. Rerun the three-step filter (filterPsmRank, filterPsmDecoy, filterPsmShared) in the opposite order (shared → decoy → rank). Do you get the same final PSM count? Explain why or why not.
  4. Connected components. Using ConnectedComponents(psm_target), find the largest connected component (the one spanning the most proteins). List its proteins and shared peptides using ccMatrix().
  5. Contaminant impact. How many target (non-decoy) PSMs in psm_target match the porcine trypsin contaminant? What fraction of all target PSMs does this represent?

## Understanding Proteomics Workflows

The typical bottom-up proteomics workflow involves:

1.  **Sample preparation**: Protein extraction, digestion (usually with trypsin)
2.  **LC-MS/MS analysis**: Liquid chromatography coupled to tandem mass spectrometry
3.  **Database searching**: Matching MS/MS spectra to peptide sequences
4.  **Protein inference**: Assembling peptides into protein identifications
5.  **Quantitative analysis**: Comparing protein abundances across samples

This chapter covers step 3's output (the PSM table) and the audit that must happen before step 4. Chapter 11 picks up protein inference from the clean PSM table this chapter produces.

## Key Proteomics Concepts

-   **PSM (Peptide-Spectrum Match)**: One MS/MS spectrum matched to one peptide sequence
-   **FDR (False Discovery Rate)**: Typically controlled at 1% using target-decoy approach
-   **Protein Parsimony**: Minimal set of proteins explaining observed peptides
-   **Missing Values**: Can occur at PSM, peptide, or protein level - handle appropriately
:::

## Loading and Understanding a Real PSM Table

`PSMatch::readPSMs()` parses an mzIdentML file into a `PSM` object — a thin, list-backed wrapper around a data frame, one row per PSM.

```{r}
psm <- readPSMs(id_file)
psm
dim(psm)
```

A real search-engine table carries far more than sequence and score. The columns that matter for auditing:

```{r}
colnames(psm)
```

| Column | Meaning |
|---|---|
| `sequence` | The matched peptide sequence |
| `spectrumID` | Which MS2 spectrum this PSM comes from |
| `chargeState` | Precursor charge assumed for this match |
| `rank` | This match's rank among all candidates for the same spectrum (1 = best) |
| `isDecoy` | `TRUE` if the matched sequence came from the reversed/shuffled decoy database |
| `pre`, `post` | The residues flanking the peptide in the source protein — needed to check cleavage rules |
| `DatabaseAccess`, `DatabaseDescription` | The protein this peptide was matched to |

## The Target–Decoy FDR Framework

Before writing any filter code, you must understand how the false discovery rate is actually estimated in proteomics. Database search engines do not know which PSMs are correct — they only produce scores. The target–decoy strategy solves this with a simple but powerful idea:

1.  **Concatenate your real protein database with a decoy database** — reversed or shuffled sequences that cannot exist in nature.
2.  **Search against the combined database.** Every PSM either matches a target (real) or a decoy (fake) sequence.
3.  **Count decoy matches as false positives.** Because decoys are biologically impossible, any PSM assigned to a decoy must be incorrect. Assuming false positives are equally likely among target and decoy matches:

$$\text{FDR} = \frac{\text{Number of decoy PSMs above score threshold}}{\text{Number of target PSMs above score threshold}}$$

This gives you the **PSM-level FDR** — the expected proportion of incorrect identifications among all PSMs that pass the score cutoff. The standard threshold is **1 % FDR** at the PSM level.

**The PSM-to-protein FDR gap.** A critical and frequently overlooked point: controlling FDR at 1 % at the PSM level does **not** guarantee 1 % FDR at the protein level. If a false PSM maps to a protein with no other evidence, that protein becomes a false identification. Conversely, if many true PSMs map to one protein, a single false PSM among them may not change the protein call. Protein-level FDR must be estimated separately — typically by applying the same target–decoy logic at the protein-group level, or by using a picked-protein FDR strategy (Savitski et al., 2015).

**In practice:**
- PSM-level FDR ≤ 1 % — the minimum standard for publication
- Peptide-level FDR ≤ 1 % — stricter, requires at least 2 PSMs per peptide
- Protein-level FDR ≤ 1 % — the gold standard; proteins with only one peptide ("one-hit wonders") are the most vulnerable to false discovery

### Computing FDR at a Score Threshold

This bundled file already carries decoy hits from the search (accessions prefixed `XXX_`), so we can compute the formula above directly instead of trusting a pre-filtered table:

```{r}
table(psm$isDecoy)

fdr_at_threshold <- function(psm, score_col, threshold) {
  above <- psm[[score_col]] >= threshold
  n_decoy  <- sum(above & psm$isDecoy)
  n_target <- sum(above & !psm$isDecoy)
  n_decoy / n_target
}

score_grid <- seq(5, 20, by = 1)
fdr_curve <- data.frame(
  score = score_grid,
  fdr   = sapply(score_grid, fdr_at_threshold, psm = psm, score_col = "MS.GF.RawScore")
)

ggplot(fdr_curve, aes(score, fdr)) +
  geom_line(color = "steelblue", linewidth = 0.8) +
  geom_hline(yintercept = 0.01, linetype = "dashed", color = "#B2182B") +
  labs(title = "Empirical target-decoy FDR vs. score threshold",
       x = "MS-GF+ RawScore threshold", y = "FDR (decoys / targets)") +
  theme_minimal()
```

Raising the score threshold shrinks the decoy fraction — this is the curve every FDR filter is implicitly walking.

### Filtering with PSMatch

`PSMatch` provides purpose-built filters instead of hand-rolling the threshold search. Applied one step at a time:

```{r}
# Step 1: keep only the best-ranked match per spectrum
psm_rank1 <- filterPsmRank(psm)

# Step 2: remove decoy hits (do this *after* using them to pick a threshold)
psm_target <- filterPsmDecoy(psm_rank1)

nrow(psm); nrow(psm_rank1); nrow(psm_target)
```

Or in one call, which applies decoy removal, rank filtering, and shared-peptide filtering together:

```{r}
psm_clean <- filterPSMs(psm)
nrow(psm_clean)
```

::: {.callout-tip}
`filterPSMs()` is convenient for a quick pass, but run the steps separately (as above) the first time you touch a new search result — you want to see each removal count individually, not just the final total, so an unexpectedly large drop at one step doesn't slide past unnoticed.
:::

## Diagnosing PSM Failure Modes

A PSM table that has passed FDR filtering can still contain systematic problems that FDR filtering does not catch. Four are worth checking on every search result.

### Missed Cleavages

Trypsin cleaves after K or R, except when followed by P. A peptide with internal (non-terminal) K/R residues represents a site trypsin should have cut but did not — a missed cleavage.

```{r}
count_missed_cleavages <- function(seq) {
  sites <- gregexpr("[KR](?!P)", seq, perl = TRUE)[[1]]
  n <- if (sites[1] == -1) 0L else length(sites)
  # the terminal residue's own K/R *is* the expected cleavage site, not missed
  if (substr(seq, nchar(seq), nchar(seq)) %in% c("K", "R")) n <- n - 1L
  max(n, 0L)
}

psm_target$missed_cleavages <- sapply(psm_target$sequence, count_missed_cleavages)

ggplot(as.data.frame(psm_target), aes(x = factor(missed_cleavages))) +
  geom_bar(fill = "steelblue") +
  labs(title = "Missed cleavages per PSM",
       x = "Missed cleavages", y = "PSM count") +
  theme_minimal()
```

A well-controlled tryptic digest is usually dominated by 0–1 missed cleavages. A distribution this broad is worth a second look at digestion conditions before trusting downstream quantification — the missed-cleavage rate is a real, searchable diagnostic, not just a filter setting.

### Charge-State Anomalies

Tryptic peptides overwhelmingly carry 2+ or 3+ charge in electrospray. Rare charge states deserve scrutiny — 1+ often means a poorly fragmented or contaminant ion, and very high charge states (5+, 6+) are uncommon enough to double-check manually.

```{r}
table(psm_target$chargeState)

ggplot(as.data.frame(psm_target), aes(x = factor(chargeState))) +
  geom_bar(fill = "darkorange") +
  labs(title = "Precursor charge-state distribution",
       x = "Charge state", y = "PSM count") +
  theme_minimal()
```

### Contaminant Hits

Search databases are normally supplemented with a contaminant database (keratins, trypsin itself, BSA) precisely so that these common laboratory proteins get identified and can be filtered out rather than silently contaminating a real hit list. Look for them directly in the protein descriptions:

```{r}
contaminant_hits <- as.data.frame(psm_target) |>
  filter(grepl("keratin|trypsin|albumin|contaminant", DatabaseDescription, ignore.case = TRUE))

unique(contaminant_hits$DatabaseDescription)
```

This search genuinely recovers a contaminant: porcine trypsin — the digestion enzyme itself, identified via its own autolysis products. This is the single most common contaminant in bottom-up proteomics and a useful sanity check that the search database was set up correctly.

### Shared Peptides

Not every peptide maps to a single protein. `describePeptides()` and `describeProteins()` summarise the peptide-to-protein mapping *before* shared peptides are removed, so you can see the scale of the problem in your own data:

```{r}
describePeptides(psm_target)
```

```{r}
describeProteins(psm_target)
```

Some peptides here match more than one protein accession, and some proteins are supported *only* by such shared peptides. `makeAdjacencyMatrix()` turns this into a peptide × protein matrix, and `ConnectedComponents()` groups the graph into clusters that must be resolved together — you cannot decide which protein a shared peptide belongs to by looking at that protein alone:

```{r}
adj <- makeAdjacencyMatrix(psm_target)
dim(adj)

cc <- ConnectedComponents(psm_target)
cc
```

Chapter 11 covers how to resolve these connected components into protein groups (unique, shared, and razor peptides). For this chapter, the practical takeaway is `filterPsmShared()`, which removes PSMs for peptides matching more than one protein — a conservative choice that trades some sensitivity for unambiguous protein assignment:

```{r}
psm_unique <- filterPsmShared(psm_target)
nrow(psm_target); nrow(psm_unique)
```

## Assembling the Identification Report

`psm_unique` above already reflects the full filtering order that matters — rank, then decoys, then shared peptides — so it *is* the report:

```{r}
psm_final <- psm_unique

  nrow(psm_final),
  length(unique(psm_final$sequence)),
  length(unique(psm_final$DatabaseAccess))
))
```

```{r}
report <- as.data.frame(psm_final) |>
  select(sequence, chargeState, DatabaseAccess, DatabaseDescription,
         MS.GF.RawScore, MS.GF.QValue, missed_cleavages) |>
  arrange(desc(MS.GF.RawScore))

head(report, 10)
```

This is the table Chapter 11 picks up: one row per confidently identified PSM, decoys and ambiguous protein assignments already removed, ready for peptide-to-protein aggregation.

## Summary

- A PSM table is a *hypothesis* list, not a ground truth — every row needs auditing before it feeds quantification.
- **Target–decoy FDR**, not a raw score cutoff, is the only defensible way to set a confidence threshold: `FDR = decoy PSMs / target PSMs` above a given score.
- `PSMatch::filterPsmRank()`, `filterPsmDecoy()`, and `filterPsmShared()` implement the three filtering steps that turn a raw search result into a clean identification list; `filterPSMs()` runs all three at once.
- **Missed cleavages**, **charge-state anomalies**, and **contaminant hits** are systematic failure modes that FDR filtering alone does not catch — check them explicitly.
- **Shared peptides** — those matching more than one protein — must be resolved before protein-level claims are trustworthy. `describePeptides()`, `describeProteins()`, and `makeAdjacencyMatrix()`/`ConnectedComponents()` make the scope of the problem visible; Chapter 11 resolves it into protein groups.
